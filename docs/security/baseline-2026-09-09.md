## Verified findings

### 1. Unauthenticated JSON API dumps stored provider responses, thread bodies, and lease tokens

- **Where:** `lib/context_bot_web/router.ex:29-34`; `lib/context_bot_web/public_data.ex:38-61`; `lib/context_bot_web/public_record.ex:4-26`; `lib/context_bot_web/controllers/response_envelopes_controller.ex:10-18`; `lib/context_bot_web/controllers/invocations_controller.ex:70-83`. Tests lock the behavior: `test/context_bot_web/controllers/response_envelopes_controller_test.exs:10-24` and `test/context_bot_web/controllers/invocations_controller_test.exs:854-986`.
- **Attacker-controlled input:** none required. Any client that can `GET` the Fly HTTP service (`fly.toml` `[http_service]`, no auth plug) can enumerate `/invocations.json` and `/anthropic_response_envelopes.json`.
- **Impact path:** `PublicData` selects `module.__schema__(:fields)` (including `Invocation` `anthropic_responses`, which is `load_in_query: false` for other queries). `PublicRecord.dump/1` Base64-encodes `:binary` columns and Erlang-decodes envelope metadata. A client therefore receives:
  - exact Anthropic `raw_body` bytes
  - `invocation_text`, `raw_notification`, `raw_thread`, `canonical_thread`, `anthropic_messages`, `full_response`, `selected_reply`
  - `research_claim_token` and `publication_claim_token`
  - per-attempt spend (`reserved_microdollars` / `settled_microdollars`)
  List endpoints call `Repo.all/1` with **no pagination**.
- **Existing protections:** HTML `GET /invocations` uses a cheap projected select and does not embed payloads (same test file, “HTML dashboard stays cheap…”). POSTs to these paths 404. `/health` stays aggregate-only. `/r/:id` 301s and does not serve sqlite writeups. There is no HTTP reprocess/reenqueue/recover.
- **Why this is not dismissed as “intentional product”:** PR `#104` (`e8dfc20`) added “Public GET-only JSON API for every product SQLite row.” That is evidence of intent in code. It still contradicts the current security posture in `SECURITY.md` (in-scope: exposure of stored invocation/thread/provider content through HTTP), `README.md` (“does not show … post bodies, prompts, or envelopes”), and `AGENTS.md` (same claim). Tests assert fixture strings such as `SECRET_BLOB_ENVELOPE` are returned to an unauthenticated `get/2`.
- **Confidence:** high (code + tests). Live production confirmation was not performed.
- **Impact:** high if the committed router is what Fly serves — confidentiality of every researched thread and every retained provider envelope; operational lease tokens; unbounded response size as the table grows.
- **Smallest fix:** stop selecting payload / token / envelope columns in `PublicData` / `PublicRecord` (keep HTML dashboard as-is), or put the JSON routes behind an operator-only control. Do not “fix” by documenting the dump as public.
- **Proposed regression test:** `GET /invocations/:id.json` and `GET /anthropic_response_envelopes.json` must 404 or omit `raw_body`, `anthropic_responses`, `anthropic_messages`, `raw_thread`, `canonical_thread`, `full_response`, and claim tokens. Keep the existing HTML test that already forbids those strings.

### 2. `mint` 1.9.3 is vulnerable to HTTP/1 memory/CPU exhaustion (CVE-2026-82728 / CVE-2026-82729)

- **Where:** `mix.lock` pin `mint@1.9.3` (via Finch 0.23.0). OSV ids `EEF-CVE-2026-82728` / `EEF-CVE-2026-82729` (aliases `CVE-2026-82728`, `CVE-2026-82729`, `GHSA-g83f-2j6r-q6m4` and the sibling GHSA). Fixed in mint **1.10.0**.
- **Attacker-controlled input:** a remote HTTP/1 peer the BEAM actually speaks to. This app’s outbound HTTP is mostly pinned (`api.bsky.app`, configured PDS, `plc.directory`, `api.anthropic.com` with `redirect: false`, `standard-reader.app`). The one hostname that can be attacker-influenced is `did:web:` resolution (`lib/context_bot/atproto/req_client.ex:68-74`): `https://{hostname}/.well-known/did.json` after label checks in `lib/context_bot/eligibility.ex:122-127`.
- **Impact path:** mint buffers an incomplete HTTP/1 status line or chunk-extension without a cap (`:max_header_list_size` does not cover those states). A malicious or redirected peer can grow `conn.buffer` until the VM is OOM-killed. `ContextBot.HTTP.BodyLimit` caps **decoded body bytes after** headers and does not close this parser hole. Req **follows redirects by default**; only `ContextBot.Research.AnthropicClient` sets `redirect: false` (`lib/context_bot/research/anthropic_client.ex:54`). `ReqClient`, `PublicClient`, `Session`, and `ReaderIndex` do not.
- **Existing protections:** `did:web` fetch runs only after a `*.bsky.team` handle forward-resolves to that DID (not for ordinary public mentions). Hostname rules reject IPs and require a letter in the TLD. Anthropic POSTs do not follow redirects. Body limits still apply to completed responses.
- **Confidence:** high that the locked version is vulnerable; **medium** that an unprivileged mention can reach a malicious HTTP/1 peer today (needs a bidirectionally verified `bsky.team` `did:web`, or a pinned origin that redirects).
- **Impact:** medium (availability of the single Fly VM). Not a credential leak.
- **Smallest fix:** bump mint to ≥ 1.10.0 (and Finch if needed). Defense in depth: `redirect: false` on ATProto/did:web/ReaderIndex Req calls, or allowlist redirect hosts.
- **Proposed regression test:** lockfile / `mix deps` assertion that mint ≥ 1.10.0; optional unit test that `ReqClient` request options include `redirect: false`.

### 3. Deploy workflow pins `superfly/flyctl-actions/setup-flyctl@master` (mutable)

- **Where:** `.github/workflows/deploy.yml:25` (`uses: superfly/flyctl-actions/setup-flyctl@master`). Semgrep `yaml.github-actions.security.github-actions-mutable-action-tag`.
- **Attacker-controlled input:** the action repo’s `master` ref, if the owner (or a compromised maintainer) moves it.
- **Impact path:** `deploy.yml` runs `flyctl deploy` with `FLY_API_TOKEN` on push to `main`. A retagged `master` can execute in that job. Other mutable tags (`actions/checkout@v7`, `erlef/setup-beam@v1`, `actions/cache@v6`) are first-party / lower urgency; they appear in CI as well.
- **Existing protections:** deploy `permissions: contents: read` only; job no-ops if `HEAD != origin/main`; CI itself has no deploy secrets. PR CI cannot publish.
- **Confidence:** high (literal `@master`). Exploitability depends on Fly action integrity, not on this repo’s app code.
- **Impact:** high *if* the action is hijacked (production deploy token).
- **Smallest fix:** pin `setup-flyctl` (and preferably checkout/setup-beam/cache) to a 40-character commit SHA.
- **Proposed regression test:** workflow lint or a small shell test that `uses:` lines in `.github/workflows/*.yml` match `@[0-9a-f]{40}` (or a documented allowlist).

## Plausible concerns

These were hypothesized, then **partially disproved**. Residual risk remains.

### Untrusted post text → privileged tools

Research puts the canonical thread in the user turn and tells the model the thread is untrusted (`lib/context_bot/research/request.ex` `CONTEXT_BOT_SYSTEM_V12`). Tools are Anthropic-hosted `web_search` / `web_fetch` with `allowed_callers: ["direct"]`. The bot does **not** declare `code_execution`; a leaked CE/bash result is a terminal `provider_response` and is not published.

A mention can still steer *which public URLs Anthropic fetches* (that is the product). That is spend + third-party fetch on Anthropic’s network, not a bot-side SSRF and not a path to the Fly volume or PDS credentials. Compact/full text can also be influenced; publication still requires `disposition=reply` and an obvious question aimed at the bot.

### Bot-side SSRF

- Images revalidated to `https://cdn.bsky.app/img/feed_fullsize/plain/...` only (`lib/context_bot/thread/media.ex:102-122`); Anthropic fetches those URLs, not the bot.
- AppView origin is a reviewed setting (`APPVIEW_URL=https://api.bsky.app`).
- `did:web` is hostname-constrained and gated on `bsky.team` verification. Residual: Req redirect-follow from that HTTPS fetch (see finding 2).
- `ReaderIndex` uses a fixed `https://standard-reader.app` URL; the document AT URI is a query parameter, not a host.
- Mix `delete_posts` verification hits `public.api.bsky.app` with encoded query params (operator shell only).

No path was found where an unprivileged mention makes **this** VM open a connection to an arbitrary internal IP.

### Spend-limit bypass via retries / concurrency

`QUEUE_CONCURRENCY` must be exactly `1` (`lib/context_bot/settings.ex` `validate_exact!`). Reservations run in `Repo.transaction(..., mode: :immediate)` and `charged_on/1` counts reserved + settled. Workers mark attempts `sent` before the Anthropic POST. Claim tokens are `research-job-{oban_id}` / `publication-job-{oban_id}` and stale claims rollback.

Public JSON **does** leak those tokens (finding 1). They are not HTTP credentials; there is no public mutation API that accepts them. A leaked token does not, by itself, start a second paid attempt from the internet. Automatic recovery can start a **new reserved** attempt after `ANTHROPIC_HTTP_TIMEOUT_MS` — that is designed spend, still under the daily cap.

Not verified: a TOCTOU that exceeds `ANTHROPIC_DAILY_BUDGET_USD` without a reservation row. Existing runner tests cover stale-claim and exhausted-budget paths; this review did not re-run them.

### Unauthorized publication

No public POST/PUT/DELETE routes. `ReplyWorker` no-ops `dry_run: true`. Publication freezes one repo/rkey and reconciles GET/PUT. Follower cards are off in committed Fly env (`FOLLOWER_POSTS_ENABLED=false`). Operator Mix tasks require `BOT_APP_PASSWORD` / live settings and are not on the HTTP surface.

### HTML XSS / open redirect

Dashboard `escape_html/1` covers actor handle and error text. Bluesky hrefs are built only from `at://{did}/app.bsky.feed.post/{rkey}`. `/r/:id` redirects only to `https://standard-reader.app/a/{did}/{rkey}` after parsing a `site.standard.document` AT URI. Homepage embed CSP allows `embed.bsky.app` scripts (third-party embed trust, not sqlite XSS).

### gitleaks “generic-api-key” hits

History: 10 findings, all `generic-api-key`, all in tests or Phoenix local config (`config/dev.exs`, `config/test.exs`, three test files). Workdir: same plus Hex `deps/` (sqlite3 C, Phoenix docs).

Inspected without copying values: `config/dev.exs:25` and `config/test.exs:24` are Phoenix-generated `secret_key_base` strings for loopback-only endpoints. Production reads `SECRET_KEY_BASE` from the environment (`config/runtime.exs:85-105`) and raises if missing. Test matches were fixture maps / rkeys, not live API keys. **No production Anthropic, Bitwarden, Fly, or app-password material was identified in git history.**

No `.gitleaksignore` is added. A future CI gitleaks job will need an allowlist for Phoenix local `secret_key_base` and should **not** scan `deps/`.

### Semgrep leftovers (not verified vulns)

- Dependabot missing `cooldown` (`.github/dependabot.yml`) — supply-chain hygiene, not an app bug.
- `Dockerfile` “missing USER” — **false positive**. `rel/overlays/bin/docker-entrypoint` `chown`s `/data` then `exec gosu nobody`.

## Hardening advice

Priority order for a follow-up (not this PR):

1. Close or redact the public JSON product dump (finding 1). Align README / AGENTS / SECURITY after the code change, not before.
2. Bump mint ≥ 1.10.0; set `redirect: false` (or an allowlist) on every Req client except where a redirect is explicitly required.
3. SHA-pin GitHub Actions, especially `setup-flyctl`.
4. Paginate or cap public list endpoints even after redaction.
5. Add Dependabot `cooldown` if you keep weekly bumps.
6. If you add gitleaks to CI: scan git history with `--redact`, exclude `deps/` / `_build` / `data/`, allowlist Phoenix local `secret_key_base` only.

Do **not** treat this report as authorization to deploy, recover invocations, or enable new public surfaces.

## Threat-model sketch (isolation)

```
untrusted Bluesky mention
        │  exact facet / reply-to-bot only
        ▼
Poller (no updateSeen) → Eligibility (tier; outage → public)
        ▼
Admission (SQLite immediate; actor/global/pending caps)
        ▼
Thread (ancestors only, depth=0; CDN image allowlist)
        ▼
Research (reserve → mark sent → Anthropic web_search/web_fetch)
        ▼
Reply (one frozen rkey; dry_run never publishes)
        │
        ├──► public HTML /health /r  (bounded)
        └──► public JSON product dump (finding 1)
```

Untrusted content can influence Anthropic tool *selection* and published wording. It should not be able to mint a second reply, skip budget reservation, or make this VM fetch an arbitrary URL. The verified exception to “stored provider responses stay off the public HTTP surface” is finding 1.
